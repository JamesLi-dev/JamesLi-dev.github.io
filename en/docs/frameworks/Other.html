其他框架

这组内容放的是主流 React / Vue 主线之外，但在特定场景里仍然很常见的方案。

这一组现在放什么​

  • Umi：偏企业后台和约定式工程体系
  • Astro：偏内容站、文档站和更轻的页面输出
  • Plasmo：偏浏览器扩展开发

怎么读会更顺​

  1. 如果是后台项目，先看 Umi
  2. 如果是内容站、博客、文档站，先看 Astro
  3. 如果是浏览器插件，直接看 Plasmo

📄️Umi

Umi 更适合放在“企业后台和约定式 React 工程”这条线上看。它不是 React 本体的替代品，而是把路由、权限、插件、工程约束这些东西先铺好，让项目一开始就别太散。

📄️Astro

Astro 适合放在“页面很多，但交互不一定很重”的那条线上看。它最吸引人的地方，不是又多了一个前端框架，而是把默认输出尽量往静态 HTML 靠，让页面先轻下来，再按需补交互。

📄️Plasmo

Plasmo 适合放在浏览器扩展开发这条线上看。它的价值不在于“又一个 React 框架”，而在于把扩展项目里原本零散又容易出错的工程细节先收好了。
